# cheapllm-bulk-apikey

**Массовое создание аккаунтов cheapllm.shop и их API-ключей — полностью автоматически, без капчи — и использование ключей через OpenAI-совместимый эндпоинт (`sk-cheap-…`, DeepSeek V4.1 Flash 1017) или локальный 9Router.**

- одна команда, один вопрос: **сколько ключей**
- каждый ключ проверяется **живым chat 200** до записи
- **прокси по желанию**: прямой режим работает; `proxies.txt` даёт каждому ключу свой выход

## 🚀 Быстрый старт

```bash
git clone https://github.com/F0Rextasy/cheapllm-bulk-apikey
cd cheapllm-bulk-apikey
npm start
```

Затем:

```
1) Mint keys       — ask how many, then run to the end
```

Введите число и Enter. Это весь процесс: новый ящик на аккаунт, регистрация, чтение ссылки подтверждения из ящика, открытие ссылки, один вызов API — и только после этого ключ попадает в `keys.txt`.

Без меню:

```bash
node src/cli.js --count 10            # 10 ключей, напрямую
node src/cli.js --count 100 --pool proxies.txt   # 100 ключей, по одному выходу на ключ
node src/cli.js verify                # проверка каждого сохранённого ключа
```

## 🎁 Что получает один аккаунт

| Пункт | Значение |
| --- | --- |
| Панель | [cheapllm.shop](https://cheapllm.shop) |
| Модель | `deepseek-v4.1-flash-1017` (контекст 131 072) |
| Во время беты | бесплатно, без лимита скорости |
| После беты | **5 000 входных + 1 000 выходных токенов в час на аккаунт**, без карты |
| Сверх этого | $0,05 / M вход · $0,009 / M кэш-вход · $0,42 / M выход |
| Параллельность | 1 активный запрос на аккаунт |
| Ключей на аккаунт | 25 в панели; инструмент берёт **один ключ на аккаунт**, так как квота и слот параллельности принадлежат аккаунту |
| Единица масштабирования | **один аккаунт = один ключ** — `--count N` создаёт N аккаунтов |

Живые цифры: `curl https://cheapllm.shop/api/config`.

## 🧭 Как это работает

```
новый ящик (temp.tf)          регистрация        подтверждение      ворота
───────────────────────  →  POST /api/signup  →  GET /verify?token  →  POST /v1/chat
plus-алиас, реальный домен   201 + ключ + cookie   302 verified        200 + текст
```

1. На temp.tf создаётся новый plus-алиас (семейство outlook/hotmail) — или на mail.tm с `--rail mailtm`.
2. `POST /api/signup {email,password,website:"",consent:true}` отвечает **201** и отдаёт ключ в том же теле.
3. Панель присылает ссылку подтверждения. Инструмент опрашивает ящик, извлекает `https://cheapllm.shop/verify?token=…` и открывает её (**302** в панель).
4. Ключ один раз вызывает `/v1/chat/completions`; 200 с текстом ассистента — это ворота. Только затем ключ записывается.

Капчи в этой цепочке нет: нечего решать и некуда вставлять токен.

## ✅ Ворота качества

- **Ключ записывается только после реального `chat 200` с текстом.** Проваленные ворота никогда не попадают в `keys.txt`.
- `node src/cli.js verify` перепроверяет каждый сохранённый ключ и сообщает LIVE/DEAD по каждому.
- Таймауты ссылки, лимит по адресу и мёртвые выходы показываются явными ошибками — инструмент никогда не «угадывает» успех.

## 🛰️ Прокси — по желанию

| Режим | Как | Действующее правило панели |
| --- | --- | --- |
| Прямой (по умолчанию) | без `proxies.txt` | **5 новых аккаунтов на адрес в час** — затем `429 Too many new accounts from this address` |
| Пул | одна строка прокси на ключ в `proxies.txt` | каждый ключ получает **свой эксклюзивный выход**; выход не переиспользуется |

С `--pool` инструмент работает **fail-closed**: если выход умирает посреди процесса, ключ падает вместе с ним; молчаливого возврата на ваш адрес нет. `outputs/exits-used.txt` фиксирует, какой выход нёс какой аккаунт.

## 🔌 Подключение к 9Router

Пункт меню `4`, или:

```bash
node src/connect-9router.js --keys keys.txt --base http://localhost:20128 --model deepseek-v4.1-flash-1017
```

Регистрирует `cheapllm.shop` как OpenAI-совместимого провайдера (`prefix cheapllm`), добавляет по соединению на ключ и печатает клиентский ключ. Любой OpenAI-совместимый роутер работает так же с `base_url: https://cheapllm.shop/v1`.

## ⚙️ Справочник CLI

```
node src/cli.js --count N [--pool proxies.txt] [--rail temptf|mailtm]
                [--delay ms] [--attempts 3] [--txt keys.txt]
                [--accounts outputs/accounts.jsonl] [--model …]
                [--auto] [--dry] [--allow-overlimit]
node src/cli.js verify [--pool proxies.txt]
```

| Флаг | Смысл |
| --- | --- |
| `--count N` | сколько аккаунтов/ключей |
| `--pool FILE` | один выход на ключ, эксклюзивно, fail-closed |
| `--rail temptf\|mailtm` | бэкенд ящика (по умолчанию `temptf`) |
| `--delay MS` | пауза между аккаунтами (по умолчанию 5000) |
| `--attempts N` | сколько выходов может сжечь один ключ (по умолчанию 3) |
| `--auto` | без вопросов (процесс и так автоматический) |
| `--dry` | показать план; ни запросов, ни записи |
| `--allow-overlimit` | только прямой режим: игнорировать локальный страж 5/час (панель всё равно откажет) |

## 📦 Выходные файлы

| Файл | Содержимое |
| --- | --- |
| `keys.txt` | один живой ключ на строку, добавляется только после chat 200 |
| `outputs/accounts.jsonl` | e-mail, пароль, ключ, выход, rail, время (локально; gitignored) |
| `outputs/ledger-YYYY-MM-DD.jsonl` | каждая попытка со статусом и длительностью |
| `outputs/exits-used.txt` | уже потраченные выходы (режим пула) |

`keys.txt`, `accounts.jsonl`, `proxies.txt` и `outputs/` в gitignore — никогда не коммитьте ключи, аккаунты и адреса прокси.

## ⚠️ Отказ от ответственности

Бесплатный уровень, лимит по адресу и поведение писем задаёт cheapllm.shop, и они могут меняться без предупреждения. Массовое создание аккаунтов с одного адреса видно оператору, а его условия разрешают ограничивать и блокировать аккаунты; используйте пул прокси и умеренные партии. Проект не связан с cheapllm.shop. Используйте на свой риск и в рамках условий провайдера.
